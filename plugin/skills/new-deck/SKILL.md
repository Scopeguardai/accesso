# New client deck

Make a presentation for one client: the story comes from that client's knowledge, the
look from that client's Design System. Work through the steps in order.

## 1. Settle the client

Work out which client the deck is for from the request.

- List the Design System artifacts available. Each client has one, titled with the
  client's name. Match the client to one by name.
- If the request names no client, or the name matches none or several, ask which client
  is meant and offer the Design System titles as choices. Never guess, and never borrow
  another client's brand.
- If the client is new and has no Design System, say so and offer to set the client up
  with the add-client skill. Do not build a deck without one.

Read the Design System's brand book before anything else. It carries the client's voice,
colour, type, layout and imagery rules, and they override any general habit of yours.

## 2. Take the brief

A brief needs: what the deck is about, who it is for, what they should do afterwards,
and roughly how many slides. Take what the request gives. Ask one short round of
questions only for what is missing and matters; if the person says to go ahead, choose
the most reasonable reading and note the assumption at the end.

## 3. Gather the client's knowledge

Facts come from two places only: the brief, and the client's knowledge folder in Google
Drive.

- The folder is `Accesso knowledge / <Client name>`. Search Drive for it and read the
  documents that bear on the brief. Search with several different words, as the
  content-flow skill describes.
- Read only that client's folder. Never use another client's documents, even for
  general background.
- A document whose title starts with "Draft" is unconfirmed: it may be used, and the
  deck's notes must ask for it to be checked.
- If Drive is not connected, say so and ask the person to connect it or attach the
  material. If the folder is missing or empty, say so and carry on from the brief alone.

Never invent a fact, figure, name or quote. Where material is missing, keep the slide
general and list what is missing at the end.

## 4. Plan the story

Follow the content-flow skill. Show the outline (one line per slide: the claim it makes)
and wait for a yes before building, unless the person asked not to be consulted.

## 5. Build the deck

Create the presentation as Claude Slides, built on the client's Design System:

- Use the Design System's colour tokens, fonts, logo and photography. Take images only
  from its Photography assets, chosen by what the brand book says each is for.
- One palette (theme) for the whole deck: the default unless the brief asks for another.
- Follow the brand book's layout rules: one idea per slide, generous space, varied
  layouts, and the opening and closing slides it describes.
- Put what the presenter should say, and the source document for each slide's facts,
  in the speaker notes.

## 6. Review and hand over

Follow the deck-review skill. Then reply with: the link to the deck, one or two
sentences on the story it tells, and the review's suggestions as a short list, including
any assumption made and any knowledge that was missing or still marked Draft.

## Revising a deck

When asked to change an existing deck, open it, change only what was asked, and keep to
the same client's Design System and knowledge. A content request changes words, not
design; a design request changes design, not words, unless one forces the other. If a
request would break the brand book, do the closest thing that does not and say what was
done instead.
